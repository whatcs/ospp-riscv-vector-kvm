# 项目当前状态

更新日期：2026-10-31

## 总览

本项目针对 Linux/KVM RISC-V Vector 上下文调度中的重复恢复问题，设计并实现 per-hart
Guest Vector owner：同一 vCPU 返回同一 hart 且寄存器内容仍有效时，只恢复 Vector 控制
CSR，跳过 `v0..v31` 的重复装入；迁移、Host/task Vector、kernel-mode Vector、CPU 状态变化、
reset 和寄存器修改等不确定情况均回退到完整恢复。

当前状态：

- 三补丁 RFC v0 已于 2026-10-27 投稿到 Linux RISC-V/KVM 邮件列表；
- RFC v0 尚未合入主线，当前等待维护者、CI 和邮件列表反馈；
- C1（`CONFIG_RISCV_ISA_V=n` 构建修复）已单独投稿并获得一条 `Tested-by`；
- 设计文档、开发补丁、测试脚本和精选原始证据已归档到本仓库；
- 当前没有真实 RISC-V Vector 硬件，因此只报告正确性、事件计数和工作量代理，不报告真实
  硬件的耗时加速比。

公开邮件线程：

- [linux-riscv RFC v0](https://lists.infradead.org/pipermail/linux-riscv/2026-October/102208.html)
- [kvm-riscv RFC v0](https://lists.infradead.org/pipermail/kvm-riscv/2026-October/013170.html)

## 已完成的主要工作

1. 梳理 RISC-V Vector 普通任务、kernel-mode Vector、KVM vCPU load/put/entry 以及
   ONE_REG 的保存恢复调用链；
2. 对照 arm64 FPSIMD/SVE 的 per-CPU last-state 与延迟恢复机制，明确可迁移部分和架构差异；
3. 将硬件 owner、Guest 内存新鲜度和 Host 恢复义务分开建模，避免把“上次运行的 vCPU”
   误认为仍驻留于硬件；
4. 实现通用 Vector owner 失效 hook、per-hart owner/cookie/generation 和 CSR-only restore；
5. 修复 preemptible kernel Vector task 恢复执行前未失效 Guest owner 的边界缺口；
6. 修复 `KVM_SET_ONE_REG` 部分 `copy_from_user()` 失败可能留下 stale owner 的问题；
7. 增加 lifetime、ONE_REG 和 partial-fault 三个 KVM selftest；
8. 完成 V=y/V=n 构建、嵌套 KVM/RVV、Host 干扰、迁移、hotplug、reset、destroy 和
   load-entry 覆盖等验证；
9. 将实验性补丁整理为“通用失效保障 → owner/CSR-only 行为 → selftests”的可审阅系列并投稿。

|---|---|
| `CONFIG_RISCV_ISA_V=y/n` 完整 Image/modules 构建 | 通过 |

| 嵌套 KVM/RVV 冒烟 | 通过 |
| 最终 30+30 RVV 正确性 A/B | 两组均 30/30 PASS |
| fastpath=N 的 full/CSR-only restore | 2194 / 0 |
| fastpath=Y 的 full/CSR-only restore | 6 / 1948 |
| 完整恢复事件减少比例 | 99.7265% |
| 严重级别内核日志 | 无 emergency/alert/critical/error |

VLEN=256 时，1948 次 CSR-only restore 对应 1.90234375 MiB 无需重新装入的 Vector 数据
寄存器架构状态。该数字不是缓存/DRAM 流量，也不是程序运行时间加速比。详细计算、证据哈希
和复核方法见[性能代理量化报告](26-现有环境性能代理量化.md)。
