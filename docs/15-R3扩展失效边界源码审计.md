# R3 扩展失效边界源码审计

日期：2026-10-20  
基线：M1C identity 修正版

## 1. 结论摘要

signal、ptrace、软中断的一般 kernel Vector 入口和 CPU PM 已能复用现有失效机制；但源码审计
发现一条 M1C 测试尚未覆盖的可抢占 kernel Vector 恢复路径：持有 preemptible kernel Vector
上下文的任务被调度走后，同一 hart 可运行 vCPU 并发布 Guest owner；原任务再次被调度进来时，
`__switch_to_vector()` 会恢复其 Vector 使用资格，却没有先清除该 Guest owner。

可以把它理解为：Guest 在 CPU 上留下了一张“这些寄存器还是我的”标签；随后一个内核任务
回来继续使用同一组寄存器，但没有先撕掉标签。寄存器一旦被内核任务覆盖，Guest 下一次仍有
机会错误命中这张旧标签。

因此 M1C 的既有 A/B 与负向结果仍然成立，但当时先把 R2 初始交付状态降为“候选”。本轮
M1D 已补上这条失效并通过定向交错测试，R2 初始行为交付现已重新闭环。

## 2. 已闭环的路径

### 2.1 signal

- 保存 signal frame 时，`save_v_state()` 调用 `riscv_v_vstate_save()`；只有真的保存硬件状态
  时才会先以 `TASK_SAVE` 失效 owner。
- 从 signal frame 恢复时只修改当前任务的内存副本并设置 `TIF_RISCV_V_DEFER_RESTORE`；真正
  返回用户态、执行 `riscv_v_vstate_restore()` 前会以 `TASK_RESTORE` 失效 owner。
- 因此“改内存”和“覆盖硬件”被分开处理，硬件覆盖前仍有统一失效点。

### 2.2 ptrace

- GET 当前任务 Vector 状态前使用 `riscv_v_vstate_save()`，实际硬件保存会触发 `TASK_SAVE`。
- SET 修改被跟踪 Host task 的内存副本；该任务重新被调度并返回用户态时走延迟恢复，硬件
  恢复前触发 `TASK_RESTORE`。
- Guest 的 KVM GET/SET_ONE_REG 不走 ptrace，但已经由专用 selftest 验证。

### 2.3 普通 kernel Vector 与软中断

- `kernel_vector_begin()` 的一般入口经 `__riscv_flush_vector_context()`，首先触发
  `KERNEL_VECTOR` 失效，再允许内核代码使用 Vector。
- `may_use_simd()` 禁止 hardirq/NMI 使用 Vector；softirq 可以使用，但仍必须经过
  `kernel_vector_begin()`，且 `get_cpu_vector_context()` 会处理 BH/preempt 约束。

### 2.4 CPU hotplug / PM

- CPU hotplug 关闭虚拟化时调用 `kvm_riscv_csr_cleanup()`；
- `CPU_PM_ENTER` 在虚拟化启用时也调用同一个 cleanup；
- cleanup 调用 `kvm_riscv_clear_former_vcpu()`，后者以 `CPU_STATE` 清除 Vector owner。

因此 CPU PM 已有与 hotplug 共用的源码闭环。当前 QEMU 环境不提供有代表性的非保留低功耗
硬件状态，PM 以源码证明为主，真实硬件到位后再补运行验证。

## 3. 新发现的 preemptible kernel Vector 缺口

关键交错如下：

1. 内核任务 A 已在 `kernel_vector_begin()` / `kernel_vector_end()` 区间内；
2. A 被调度走，`__switch_to_vector()` 保存必要的 kernel Vector 状态；
3. 同一 hart 运行 QEMU vCPU B，B 的 put 发布 Guest owner 并保留数据寄存器；
4. A 再次被调度进来；现有 `__switch_to_vector()` 只重新启用 Vector 或设置
   `RISCV_PREEMPT_V_NEED_RESTORE`，没有清 Guest owner；
5. A 恢复/继续执行 Vector 指令并覆盖寄存器；B 下次 load 仍可能误判 hit。

缺口不在普通首次 `kernel_vector_begin()`，而在“已经持有 preemptible kernel Vector 上下文的
任务恢复执行”这一条旁路。

## 4. M1D 最小修复

修复是在 `__switch_to_vector()` 发现 next task 持有 active preemptible Vector 上下文时，
在它恢复或继续使用寄存器前调用 `riscv_v_owner_invalidate(KERNEL_VECTOR)`。这样同时覆盖：

- 自愿 schedule 后继续使用、寄存器按 caller-saved 处理的分支；
- 被抢占后需要从 `kernel_vstate` 恢复的分支。

定向测试不需要 100 次循环：把 preemptible kernel Vector worker 和一个 L2 vCPU 固定到同一
CPU，让 worker 在 begin/end 区间主动睡眠，期间让 vCPU 发布 owner；worker 恢复时必须先出现
`kernel_vector` invalidate，随后 Guest RVV 数据校验保持通过。使用 20 次 RVV 作为交错窗口，
并保留完整 trace。
